# Outcome estimator discovery protocol (active: v3)

Status: the active protocol is **outcome-discovery-v3**, defined in the
"Aggregate-shift response protocol" section below. The v1/v2 material is
retained for audit history only; sections explicitly marked historical are
superseded and must not be used to generate or interpret new reports. This
revision must be committed before generating any report described as
preregistered. Any report generated before this commit remains exploratory.

Status: v2/v3 protocol text is available for reproducibility, but strict
committed-preregistration was not satisfied for the exploratory reports
`report-5.json` and `report-6.json`. No result from those reports is
confirmatory evidence; future reruns cannot retroactively change that status.
Protocol date: 2026-10-05.

## Amendment history (outcome-discovery-v2)

Independent statistical and privacy reviews found that the original v1 plan
would overstate what aggregate data can establish. The v2 text below supersedes
the inferential claims while preserving the original protocol for auditability.
The v2/v3 amendment text existed in the working tree when `report-5.json` and
`report-6.json` were generated, but it had not been committed. Those reports
are exploratory and do not meet the committed-preregistration gate.

- Event-level binomial intervals are explicitly exploratory and not
  customer-cluster adjusted. Candidate statuses are screening labels, never
  release approval or proof of improvement.
- Temporal placebo windows are evaluated once each, without replacement. They
  overlap and are dependent; the report does not expose a false-positive rate,
  Wilson interval, or acceptance verdict.
- Injected deterministic shifts are not statistical power or MDE. These are
  omitted because published aggregates do not retain the customer-level
  sampling distribution needed to estimate those quantities honestly.
- Source labels are mapped to the bounded OPBENCH dimension vocabulary before
  output. No arbitrary source category text is serialized.

The amendment narrows claims but does not retroactively preregister the two
exploratory reports. A proper confirmatory calibration requires
customer-cluster sufficient statistics or local customer-level resampling
followed by the same privacy review.

## Amendment history (outcome-discovery-v3)

The v3 protocol restores a deterministic aggregate-shift check so the
implementation is tested against the T1 2/5/10 pp scenarios without misnaming
that check as statistical power. It applies to future runs as a frozen
reproducibility protocol, not as a retroactive preregistration of existing
reports:

- At the fixed `2025-01` boundary, inject 2, 5, and 10 percentage-point
  reductions into each registered cell's three post months, independently for
  each target cell and in both hash halves. Use largest-remainder allocation
  over published monthly denominators. Counts are clamped at zero; if an
  injected row would violate `k=10`, omit that row and let the estimator fail
  closed on its now-incomplete window.
- Report the fraction of registered cells classified `improved` at each
  injected shift, grouped by the preregistered mean monthly support bins
  `<500`, `500-999`, `1000-1999`, and `>=2000`. A bin with fewer than ten
  registered cells is suppressed; missing or suppressed rows are not removed
  from its denominator.
- This is the deterministic algorithm's response to altered aggregate counts,
  not statistical power, a sampling distribution, a calibrated minimum
  detectable effect, or evidence a real change can be detected at that rate.
  The 80% threshold over the three injected values is labelled an
  `algorithmic_80pct_shift_threshold_pp`, not an MDE. If no injected value
  reaches it, report `>10 pp` only for bins with at least ten cells.
- Temporal placebo output remains a finite, overlapping-window descriptive
  screen. Report its empirical candidate-window frequency and whether that
  observed frequency is at or below the 5% screening bound, but do not call it
  a calibrated false-positive rate or general pass claim. The preregistered
  random seed selects distinct eligible boundaries without replacement;
  every eligible boundary is evaluated at most once.

The existing `report-5.json` and `report-6.json` remain exploratory even if
regenerated byte-for-byte under this protocol. A new report may be described
as preregistered only when this exact protocol revision is committed before
that report is generated.

## Question and interpretation

Can a proposed bank-support change be followed by a sustained, measurable shift
in a binary service metric that is larger than ordinary month-to-month noise?
This is an observational monitoring question, not a causal-impact claim. The
bank extract has no real intervention/release history, and both customer-hash
halves would be exposed to a real platform-wide release. Therefore the hash
halves are independent replication cohorts, never treated-versus-untreated
controls. The engine must never report that a release caused an outcome.

## Frozen input contract and scope

The estimator consumes the `scripts/aggregate/bank_cells.py` NDJSON format
without schema translation. Each input object has exactly the fields
`metric`, `dims`, `half`, `period`, `numerator`, and `denominator`; `period` is
`YYYY-MM`, `half` is `discovery` or `holdout`, and numerator is the observed
positive count out of denominator. The estimator accepts only rows already
produced by that aggregate-only, complementary-suppression-aware builder. It
does not read raw tables, identifiers, free text, or sidecar counts.

The registered cell universe is every distinct `(metric, dims)` represented
in the input. For each metric, the comparator consists of sibling cells that
match all dimensions except one: prefer `reason_category`, then `category`,
then `channel`. This makes M1/M6 comparisons same-channel/other-reason,
M4/M5 comparisons other categories, and channel-only metrics comparisons
other channels. The control is the aggregate of *published* sibling cells;
it is not asserted to contain suppressed or globally absent categories. If a
cell needed for the comparator is absent from any window, the estimate is
inconclusive rather than reconstructed. All metrics and registered cells are
attempted and failures remain in summary denominators.

## Frozen time design

Use only complete month labels present in the input. The upstream bank-cell
builder excludes partial boundary months `2023-06` and `2026-06`; the raw
extract therefore spans 37 calendar labels while this analysis is expected to
use at most 35 full months. Sort periods lexicographically as calendar months.
For a hypothetical release boundary, exclude its month as a washout, use the
three immediately preceding complete months as pre and the three immediately
following complete months as post. Require all six months in every treated,
control, and hash-half cohort. No window is shortened after seeing results.

## Estimator and decision rule

For each cell and hash half, compute the descriptive difference-in-differences
in proportions:

`effect = (treated_post_rate - treated_pre_rate) - (control_post_rate - control_pre_rate)`.

Negative means the treated cell's positive outcome rate fell relative to its
published sibling comparator. The unpooled binomial variance is the sum of
`p*(1-p)/n` for the four proportions. Report a two-sided interval around the
effect. Apply Bonferroni family-wise correction at alpha `0.05` over every
registered cell and both hash halves for each hypothetical release boundary.

Minimum support is 1,500 treated and 1,500 control observations in each
pre/post window for each half (equivalent to 500 per 30-day month on average),
with all component cells published by the upstream `k=10` rule. Require an
80%-power minimum detectable effect (MDE) no greater than 10 percentage points
for that half; otherwise status is `inconclusive` with reason `underpowered`.
Materiality/equivalence margin is frozen at 2 percentage points. Return:

- `improved`: both halves have effect at most -2 pp and corrected interval
  upper bounds below -2 pp;
- `worsened`: both halves have effect at least +2 pp and corrected interval
  lower bounds above +2 pp;
- `no_detectable_change`: both corrected intervals fit wholly inside [-2,+2]
  pp (evidence of practical equivalence, not proof of no effect);
- `inconclusive`: every other case, including insufficient support, missing
  comparator cells, opposite half directions, or excessive MDE.

The output contains effect and interval, treated pre/post n, control identity,
MDE/power note, and status. It does not publish control margins or row-level
data. `improved` and `worsened` remain descriptive associations.

## Historical v1 placebo protocol (superseded; do not execute)

There is no known real release in the bank extract. Generate 1,000 fake release
boundaries by sampling with replacement from every boundary having the six
required full months, using Python `random.Random(20261005)`. Run the exact
registered estimator and correction, without tuning thresholds. A placebo
draw is a false-positive draw if any cell is labelled `improved` or `worsened`.
Report the measured family-wise rate and Wilson 95% interval. The acceptance
bound is a measured rate <=5%; if it exceeds 5%, report the failure and do not
claim the estimator is validated. Failed/ineligible cells and dates are
counted, not silently dropped.

## Historical v1 power protocol (superseded; do not execute)

For each eligible cell, fake date, and hash half, inject reductions of 2, 5,
and 10 pp into the treated post-period numerator only, leaving denominators
and sibling controls unchanged. Clamp at zero and use deterministic
largest-remainder rounding across post months so injected totals are exact to
one count. Additionally scan 1-20 pp in one-pp increments to estimate MDE.
Summarize detection rate by pre-registered mean treated observations per
30-day month bins `<500`, `500-999`, `1000-1999`, `>=2000`; MDE is the smallest
injection with >=80% `improved` decisions, or `>20 pp/not reached`. Include
every registered cell in a named underpowered-cell list (no counts in that
list). This simulation validates sensitivity to an injected arithmetic shift;
it is not evidence that a real release would produce the shift.

## Aggregate-shift response protocol (outcome-discovery-v3; not power)

At the fixed `2025-01` boundary, for each registered cell and hash half, inject
reductions of 2, 5, and 10 pp into the treated post-period numerator only,
leaving denominators and sibling controls unchanged. Clamp at zero and use
deterministic largest-remainder allocation across post months so the aggregate
requested shift is exact to one count unless clamped. If a changed row would
violate `k=10`, omit it and let the estimator report the target inconclusive.
Summarize the algorithm's detection rate by the mean published monthly support
bins `<500`, `500-999`, `1000-1999`, `>=2000`; do not call this statistical
power or a calibrated MDE. Report the first injected shift with at least 80%
`improved` decisions as an algorithmic response threshold, or `>10 pp/not
reached`; suppress rates for bins with fewer than ten registered cells.
Include every registered underpowered cell in a named list without counts.
This simulation tests the estimator's deterministic response to arithmetic
shifts; it is not evidence that a real release would produce the shift.

## Multiplicity, privacy, determinism, and exclusions

- Multiplicity family: all `(metric, dims)` cells represented by the input,
  tested in both hash halves at every fake boundary; use Bonferroni FWER 5%.
- Preserve the upstream `k=10` plus complementary suppression. A test scans
  every emitted binary numerator, denominator, and complement; values 1-9
  must not be published. No new control totals/margins are emitted.
- Output stable sorted JSON with canonical separators/order. The full command
  must regenerate byte-identical validation reports on repeated runs.
- Publish aggregate status counts, placebo counts/rate, power by sample-size
  bin, and dimension labels for underpowered cells only. Never publish IDs,
  free text, per-customer data, raw rows, or control-cell count margins.
- No release history, causal estimate, financial uplift, real treatment
  assignment, randomized rollout, or external model call is available here.

## Preregistered command contract

1. Run `python -m scripts.aggregate.outcome.outcome_estimator --data-root
   <local-data-root> --out <outside-repo>/outcome-report.json`. This is the
   canonical CLI; the legacy module `scripts.aggregate.outcome_estimator`
   delegates to the same v3 implementation. The command builds bank-cell rows
   in memory via the upstream aggregator and does not persist NDJSON.
2. Repeat the same command to a separate output path and compare report
   SHA-256 values. Generated reports stay outside Git during validation;
   only disclosure-safe aggregate summaries may be committed after review.
