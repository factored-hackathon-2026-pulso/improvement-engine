# FLOW1: flow edits the engine may propose (registry kind `flow`)

The engine proposes FLOWS and nothing else of the knowledge family. A flow change is the riskiest kind the engine drafts (agent-core's double yardstick looks at scenario outcomes and metrics, not at the graph), so the compiler is conservative: it only ADDS, it never deletes or loosens, and it never edits a protected node or an edge that leaves one. Code: `seams/crates/reasoning/src/flow_edits.rs` (compiler and recompute), mapping rows in `seams/crates/reasoning/fixtures/mapping_table.json` (kind `flow_edit`), suite mechanism `flow_*` in `scripts/regression/build_suite.py`.

## What agent-core enforces (read in agent-core main 4fa1a8d, 2026-10-05)

* Nodes (`domain/nodes.py`): decide, rule, collect, tool (read) and write tool (`action_from` or `draft`), confirm, verify, respond, escalate, end, knowledge, agent, suggest, subflow, await_approval, transfer. Every node lists ALL its result labels (G0-03): collect `ok`+`max_attempts`, tool `ok|error|timeout|denied`, respond `next`, rule `true|false`, escalate and end have none.
* Freeze rules that an edit can break: G0-03 (labels, reachability), G0-04 (no cycle without a waiting node), G0-05 (a write is reached only through `confirm.yes` and goes straight to its `verify`), G0-06 (every failure branch ends in a safe exit: collect, escalate, a safe `end`, or a chain of plain responds without claims), G0-12 (every template covers the agent locales es and pt), G0-26 and G0-27 (transfer), G0-29 (`capture_start` only on the entry chain), AG-04 (a read slot must have a collect), REG-PIN (an exact pin of the agent to its entry flow) and REG-VERSION (a new version of an entity must be higher; the registry cascades patch bumps to non-drafted referrers).
* `evaluate` runs scripted scenarios on the real engine with sandboxed tools. It scores `expect.outcome`, `escalated`, `actions_verified` and event assertions (`engine.escalated{reason_code,target_queue}`, `engine.run_closed{outcome}`, `engine.tool_called{status}` and presence/absence of events). Events carry no node id, no template id and no tool id (`engine.tool_called` has status, latency, attempt). Responses are not read.
* The Core protects interrupts (`locked`); it does NOT protect flow nodes, policies or tools. The protection below is the engine's.

## Compiler guarantees (and denial codes)

Position ids come from a menu computed from the real graph; the Builder picks one id and one preset id (reviewed es/pt text or a validator, both in the mapping data). Closed denial codes: `op_unknown`, `invalid_graph` (dangling edge, duplicate or unreachable node, wrong labels), `flow_unsupported` (task and builder flows), `position_unknown`, `edge_frozen` (the edge leaves a protected node), `position_not_allowed`, `node_protected`, `validator_exists`, `validator_invalid`, `preset_invalid`, `text_not_clean`, `translation_copy`, `slot_taken`, `no_error_exit`, `already_applied`, `edit_limit` (3 engine nodes per flow), `node_limit`, `template_taken`, `invariant_broken`.

After building the result the compiler recomputes, independently of how it was built: entry unchanged; every protected node byte-identical; every old edge reaches the same old node when the new nodes are contracted; new nodes are plain responds or collects whose exhausted attempts go to an existing escalation; every node reachable; every failure branch that was a safe exit still is; at most 60 nodes. The flow version gets a minor bump; the agent gets a patch bump and an EXACT entry-flow pin follows the new flow version (REG-PIN); new templates are version 1.0.0 with es and pt. The structured facts of the edit (op, from/to node types, new nodes, exits, protected unchanged, pass-through, reachable escalations before/after) are stored in the proposal and are what the independent review (mimo pro) reads.

## Not measured, said in the dossier

Tool identity, wording, and for an ask the failure exit after the extra turn: the pulso-min guards that run the whole path (tool failure, amount escalation, cancel) take a different number of turns on the candidate, so the suite keeps only the guards whose script ends before the edited position and adds structural guards. See `REGRESSION_SUITES.md` and the dossier text.
